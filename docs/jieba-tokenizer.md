# Jieba tokenizer

The v0.5 Jieba tokenizer is a pure-Go port of the cppjieba algorithms used by
zvec commit `58375ff`. It has no CGO dependency. The implementation reads the
same plain-text dictionary, user-dictionary, and HMM model formats, but the
large production language resources are deliberately not embedded in the Go
module.

`NewJiebaTokenizer` accepts a context because construction validates and loads
the selected resources. `Tokenize` also accepts a context and returns owned
`Token` values. Offsets are uint32 byte offsets in the original byte sequence;
positions are contiguous, zero-based output positions, including overlapping
search terms. Cancellation returns no partial tokenizer or token list, and an
instance is immutable and safe for concurrent tokenization.

The four baseline cut modes are available:

- `JiebaCutModeSearch` is the default. It runs mixed dictionary/HMM
  segmentation and adds known two- and three-codepoint search terms before
  each parent term.
- `JiebaCutModeMix` uses the dictionary maximum-probability path and applies
  HMM segmentation to unknown singleton runs.
- `JiebaCutModeFull` emits overlapping dictionary candidates.
- `JiebaCutModeHMM` performs Viterbi segmentation without a dictionary and
  preserves cppjieba's ASCII letter, digit, and decimal grouping.

Search and mix modes require `jieba.dict.utf8` plus `hmm_model.utf8`; full mode
requires only the dictionary; HMM mode requires only the model. The resource
directory resolves in this order: `JiebaTokenizerOptions.DictDir`, the
`ZVEC_JIEBA_DICT_DIR` environment variable, then `DefaultJiebaDictDir`.
`UserDictPath` accepts one or more paths separated by `|` or `;` and applies
only to the constructed tokenizer.

```go
tokenizer, err := core.NewJiebaTokenizer(ctx, core.JiebaTokenizerOptions{
    DictDir:      "/opt/zvec/jieba",
    UserDictPath: "/opt/zvec/jieba/domain.dict.utf8",
    CutMode:      core.JiebaCutModeSearch,
})
if err != nil {
    return err
}
tokens, err := tokenizer.Tokenize(ctx, "自然语言处理")
```

For parity, spaces, tabs, line feeds, U+FF0C fullwidth comma, and U+3002
ideographic full stop are returned as individual tokens between segmented
ranges. The pinned cppjieba decoder's permissive treatment of continuation,
overlong, and surrogate byte sequences is retained. An incomplete sequence or
a lead byte at or above 0xF8 rejects the complete input with
`ErrInvalidJiebaUTF8`; this explicit error replaces the baseline wrapper's
otherwise silent empty output.

The repository contains only tiny synthetic resources for deterministic tests.
Production callers must separately provide suitably licensed cppjieba-format
resources. The cppjieba MIT notice for the ported algorithms is reproduced in
`NOTICE`.

Jieba now composes with token filters, posting lists, query parsing, BM25, and
Collection FTS execution through `FTSIndexParams`; configured resource failures
still surface explicitly.

Verification includes an exact fixture generated by the baseline C++ wrapper,
all four cut modes, resource-resolution and failure matrices, user-dictionary
isolation, decoder edge cases, cancellation, concurrent use, fuzzed source
ranges, an example, and a throughput benchmark:

```sh
go test ./internal/core -run '^TestJiebaTokenizer'
go test ./internal/core -run '^$' -fuzz '^FuzzJiebaTokenizer$'
go test ./internal/core -run '^$' -bench '^BenchmarkJiebaTokenizer$' -benchmem
```
