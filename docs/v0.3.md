# v0.3 capability matrix

v0.3 adds native in-memory ANN, scalar quantization, and original-vector
refinement to the pure-Go engine. Its behavioral baseline remains zvec commit
`58375ff`. Collection storage continues to use native format version 1, so
v0.3 opens collections created by v0.1 and v0.2 without migration.

## Supported

| Area | v0.3 behavior |
| --- | --- |
| Earlier surface | All v0.1 lifecycle/CRUD/exact search and v0.2 SQL/filter/index-DDL/column-DDL/Optimize behavior |
| Scalar quantization | Deterministic FP16, per-vector INT8, and packed INT4 codes with L2, IP, cosine, and MIPS-L2 scoring |
| Rotation and refinement | Reversible FHT/Kac preprocessing for INT8/INT4 and exact retained-original reranking for dense queries |
| Training | Context-aware deterministic k-means with reservoir or k-means++ initialization and explicit empty-cluster policies |
| Dense IVF | Build, NProbe search, checksummed native persistence/reopen, concurrency-safe incremental assignment, and collection routing |
| Dense HNSW | Deterministic build, EF search, checksummed native persistence/reopen, atomic incremental writes, and collection routing |
| Sparse HNSW | CSR-backed inner-product build/search, checksummed native persistence/reopen, atomic incremental writes, and collection routing |
| Query controls | SQL filtering, metric-aware radius, projection, explicit Linear truth scans, bounded HNSW cache warming, and dense refinement |
| Lifecycle integration | CreateIndex backfill validation, quantized write validation before WAL, Optimize acceptance, Stats completeness, and deterministic reopen |

Dense Flat, HNSW, and IVF collection queries support unquantized execution and
FP16/INT8/INT4 scalar codes where schema validation permits them. Sparse Flat
and HNSW support original values or FP16-rounded values and use inner product.
Optional rotation is accepted only for dense INT8/INT4 definitions. Full-probe
IVF is exact relative to the matching Flat representation; partial-probe IVF
and HNSW are quality-gated against Flat truth.

The collection layer currently builds a query-local runtime index from the
durable live-document snapshot. Standalone IVF, dense HNSW, and sparse HNSW
artifacts have independent magic/version/length/checksum envelopes, but are not
yet attached to collection segments. This affects query cost, not durability:
the schema and source vectors are authoritative, and reopen rebuilds identical
runtime state.

## Explicitly unavailable

The following requests return `ErrNotSupported`; v0.3 does not silently replace
them with Flat or another algorithm:

- RaBitQ, HNSW-RaBitQ, Vamana, PQ, and DiskANN execution;
- FTS tokenization, postings, parsing, BM25, and FTS index execution;
- MultiQuery and RRF, weighted, or callback rerankers;
- ANN-native group-by traversal (HNSW/IVF group-by requires explicit Linear);
- scalar-quantized or refined group-by and sparse original-vector refinement;
- IVF's alternate SOAR layout;
- importing or reading the C++ collection format.

Schemas continue to validate and round-trip public parameters for later
algorithms when that is useful for compatibility. Any operation that would
need to execute such an algorithm rejects it at the operation boundary.

## Compatibility and verification

The public library version is 0.3.0 and `NativeDiskFormatVersion` remains 1.
Public enum assignments remain pinned to the C++ headers at `58375ff`; the
serialization layer retains its explicit DiskANN/Vamana mapping. Native Go
collection and standalone-index files are not C++ compatible.

Release quality tests measure dense and sparse HNSW recall@10, scalar-quantized
HNSW recall@10, partial-probe IVF recall@10, full-probe IVF equivalence, and
Collection ANN behavior across Optimize and reopen. The common dense benchmark
reports latency, allocations, and recall on the same Flat, IVF, HNSW, and
INT8-HNSW corpus:

```sh
go test ./internal/core -run '^$' \
  -bench '^BenchmarkV03DenseSearchQuality$' -benchmem
```

The release gate also runs all package/example tests, `go vet`, the race
detector, active storage/parser/codec fuzz targets, storage and DDL crash tests,
and no-CGO Darwin/Windows compilation.
