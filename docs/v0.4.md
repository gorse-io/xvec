# v0.4 capability matrix

v0.4 adds RaBitQ, HNSW-RaBitQ, Vamana, product quantization, and DiskANN to
the pure-Go engine. Its behavioral baseline remains zvec commit `58375ff`.
Collection storage remains native format version 1, so v0.4 opens collections
created by v0.1 through v0.3 without migration.

## Supported

| Area | v0.4 behavior |
| --- | --- |
| Earlier surface | All v0.1 lifecycle/CRUD/exact search, v0.2 structured-query/DDL/Optimize, and v0.3 quantization/IVF/HNSW behavior |
| RaBitQ | Deterministic clustered rotation, portable split codes, and one-bit/full-bit L2, IP, and cosine estimation |
| HNSW-RaBitQ | Original-vector graph construction, coarse/full-code traversal, exact optional refinement, native persistence/reopen, and atomic incremental generations |
| Vamana | Deterministic RobustPrune graph construction, L2/IP/cosine/MIPS-L2 EF search, scalar quantization, exact refinement, persistence, and atomic additions |
| Product quantization | Deterministic 8-bit contiguous chunks, 256-entry codebooks, L2/IP distance tables, restorable state, and batch encoding/lookup |
| DiskANN | Vamana-derived graph construction, PQ frontier traversal, exact disk-node scoring, FP32/FP16 collection input, all four dense metrics, and complete native persistence |
| Portable disk I/O | Versioned 4 KiB sector records, packed or multi-sector nodes, ReaderAt batching, bounded LRU caching, CRC32C, and atomic publication |
| Lifecycle integration | HNSW-RaBitQ, Vamana, and DiskANN query/CreateIndex/DropIndex/Optimize/Stats/reopen routing without fallback |

HNSW-RaBitQ accepts dense FP32 fields with 64–4095 dimensions and L2, inner
product, or cosine. Vamana accepts all supported dense field types and all
four dense metrics, with FP16/INT8/INT4 scalar quantization where ordinary
schema validation permits it. Its public `Linear` option remains an exact
truth path.

DiskANN accepts dense FP32 and FP16 fields. Every non-empty index uses its own
8-bit PQ model to order graph candidates, then scores every expanded node from
the original FP32-view vector. Cosine uses normalized PQ traversal; MIPS-L2
uses reconstructed-code norms. Filter and radius rejection never prevent a
node from serving as a graph bridge. `UseRefiner` expands the candidate budget
by the pinned factor of ten and applies exact final scoring.

Standalone HNSW-RaBitQ, Vamana, PQ, and DiskANN artifacts are native Go
formats, not C++ formats. Collection still rebuilds query-local ANN state from
the durable live-document snapshot; attaching standalone ANN artifacts to
immutable collection segments is a later lifecycle optimization.

## Explicitly unavailable

The following requests return `ErrNotSupported`; v0.4 does not silently
substitute another algorithm:

- FTS tokenization, postings, parsing, BM25, and FTS index execution;
- MultiQuery and RRF, weighted, or callback rerankers;
- ANN-native group-by traversal (ANN group-by requires explicit `Linear`);
- scalar-quantized or refined group-by and sparse original-vector refinement;
- DiskANN public scalar `Quantize` settings, which are distinct from its
  mandatory internal PQ representation;
- DiskANN incremental mutation of an already built standalone artifact;
- IVF's alternate SOAR layout;
- importing or reading the C++ collection or standalone-index formats.

## Compatibility and verification

The public library version is 0.4.0 and `NativeDiskFormatVersion` remains 1.
Public enum assignments remain pinned to the C++ headers at `58375ff`; the
serialization layer retains its explicit DiskANN/Vamana mapping. Every new
standalone artifact begins with its own magic and format version.

The release quality matrix fixes a deterministic DiskANN recall@10 floor of
0.80 across L2, inner product, cosine, and MIPS-L2, and requires identical
results before and after reopen. The pinned corpus currently produces 1.000,
0.992, 1.000, and 1.000 respectively. Resource tests instrument ReaderAt to
enforce configured worker concurrency and the 128-sector batch budget. A
subprocess kill test interrupts an atomic DiskANN save after its temporary
file appears and requires the published path to reopen as one complete old or
new generation.

The shared v0.4 benchmark reports latency, allocations, and recall@10 for
Flat, HNSW-RaBitQ, Vamana, and DiskANN on one corpus. It also reports the
DiskANN artifact size; a separate benchmark records end-to-end DiskANN build
time and allocations:

```sh
go test ./internal/core -run '^$' \
  -bench '^BenchmarkV04(DenseSearchQuality|DiskANNBuild)$' -benchmem
```

The release gate also runs all package and example tests, `go vet`, the race
detector, complete and node-level DiskANN fuzz targets, process-kill storage
tests, and no-CGO Linux, macOS, and Windows builds on amd64 and arm64.
