# v0.5 capability matrix

v0.5 adds full-text analysis and retrieval, snapshot-consistent hybrid search,
configurable result fusion, and process resource governance to the pure-Go
engine. Its behavioral baseline remains zvec commit `58375ff`. Collection
storage remains native format version 1, so v0.5 opens collections created by
v0.1 through v0.4 without migration.

## Supported

| Area | v0.5 behavior |
| --- | --- |
| Earlier surface | All v0.1 lifecycle/CRUD/exact search, v0.2 structured-query/DDL/Optimize, v0.3 in-memory ANN, and v0.4 RaBitQ/Vamana/DiskANN behavior |
| Tokenizers | Byte-preserving whitespace, Unicode 17 standard, Unicode 17 codepoint ngram, and pure-Go Jieba search/mixed/full/HMM modes |
| Token filters | Unicode 17 lowercase, baseline ASCII folding, and all 36 Snowball 3.1.1 stemmers with pinned aliases |
| FTS storage | Prefix-compressed term dictionaries, bitpacked postings, tf/document length, delta-varint positions, seeking, CRC32C, cross-segment statistics, and deletion-aware compaction |
| FTS query | Analyzed term, exact phrase, implicit/explicit boolean, parentheses, must, must-not, expression, and natural-match execution |
| Scoring | BM25 with deletion-aware corpus statistics, deterministic top-k, and streaming dictionary merge |
| Hybrid retrieval | One live snapshot and one SQL scalar filter across dense vector, sparse vector, and FTS branches through `Collection.MultiQuery` |
| Fusion | Default/explicit reciprocal-rank fusion, metric-normalized weighted fusion, and context-aware callback fusion with panic containment and strict output validation |
| Runtime governance | One-shot process configuration, context-aware query/maintenance admission, conservative scratch-memory budgeting, worker bounds, planner thresholds, `slog`, and Jieba fallback resources |
| Statistics and cache | Runtime active/peak/queued/completed counters, expanded collection segment/deletion/memory estimates, and active per-handle DiskANN node-cache budgets |

MultiQuery requires at least two branches. Each branch has its own bounded
candidate count, while the final projection and scalar filter are shared. BM25
corpus statistics are formed before scalar candidate filtering, so the filter
does not alter IDF or average document length. A caller reranker runs after the
collection read lock is released; its result is checked against the immutable
candidate snapshot and rematerialized before return.

Planner thresholds select only exact-equivalent execution paths. Selective
scalar filters can force exact vector scans or FTS candidate seeks; broad
inverted candidates can switch to a forward scan. No threshold changes match,
score, or durability semantics.

## Explicitly unavailable

The following capabilities remain unavailable; v0.5 does not silently
substitute another algorithm. Representable algorithm combinations return
`ErrNotSupported`, while `Collection.Query` rejects a non-vector target as
`ErrInvalidArgument`:

- standalone single-branch FTS through `Collection.Query` (FTS is currently a
  MultiQuery branch and therefore needs a second retrieval branch);
- FTS `CreateIndex` backfill and FTS-aware `Optimize`; an FTS field must be
  declared when the collection is created;
- persisted FTS artifacts attached to immutable collection segments—the public
  query currently rebuilds its dictionary from the durable live snapshot;
- ANN-native group-by traversal (ANN group-by requires explicit `Linear`),
  scalar-quantized/refined group-by, and sparse original-vector refinement;
- DiskANN public scalar quantization, DiskANN incremental standalone mutation,
  and IVF's alternate SOAR layout;
- CPU thread binding, which portable Go cannot apply to individual scheduler
  worker threads;
- importing or reading C++ collection and standalone-index formats.

The scratch-memory limit is admission control over conservative encoded-data
estimates, not a hard Go heap or process RSS cap. A zero limit intentionally
leaves memory sizing to the Go runtime. Zvec accepts an application-owned
`slog.Logger` but does not own file output or rotation.

## Compatibility and verification

The public library version is 0.5.0 and `NativeDiskFormatVersion` remains 1.
Public enum assignments and planner defaults remain pinned to the C++ headers
and sources at `58375ff`; native FTS and ANN artifacts retain their independent
magic, version, length, and checksum boundaries.

The release-level hybrid matrix runs dense, sparse, and boolean FTS branches
through default RRF, explicit RRF, weighted, and callback fusion. It requires
the shared scalar filter and projection to hold, scores to remain finite,
default and explicit RRF to agree, collection statistics to be populated, and
all results to remain value-identical after a read-only reopen.

The v0.5 regression gate runs all package and example tests, `go vet`, the race
detector, relevant tokenizer/filter/posting/parser/BM25/MultiQuery/reranker and
runtime fuzz targets, a no-CGO build, and Linux, macOS, and Windows build
matrices. The hybrid and resource benchmarks are:

```sh
go test . -run '^$' \
  -bench '^(BenchmarkV05HybridMultiQuery|Benchmark.*Reranker|BenchmarkRuntimeAdmission)$' \
  -benchmem
go test ./internal/core -run '^$' \
  -bench '^(Benchmark.*Tokenizer|Benchmark.*TokenFilter|BenchmarkFTS.*|BenchmarkSearchFTSBM25|BenchmarkMergeFTS.*)$' \
  -benchmem
```
