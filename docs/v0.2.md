# v0.2 capability matrix

v0.2 adds structured filtering and collection lifecycle operations to the
native Go engine. Its behavioral baseline remains zvec commit `58375ff`, and it
continues to read every v0.1 native collection because
`NativeDiskFormatVersion` remains 1.

## Supported

| Area | v0.2 behavior |
| --- | --- |
| v0.1 surface | All v0.1 lifecycle, CRUD, Fetch, exact dense/sparse Flat, projection, radius, and group-by behavior |
| SQL frontend | Positioned lexer/parser, typed AST, schema binding, normalization, three-valued evaluation, and deterministic errors |
| Predicates | Scalar and array comparisons, NULL, IN/NOT IN, LIKE/NOT LIKE, prefix/suffix patterns, `array_length`, and contain-any/all |
| Query plans | Analyzed forward plans shared by dense, sparse, group-by, and DeleteByFilter execution |
| Scalar INVERT | Exact candidates for equality, range, IN, NULL, array length/contain, prefix, and optional extended suffix or prefix/suffix wildcard routing |
| Filtered queries | Exact Flat top-k/radius and group-by over SQL-filtered live document versions with normal projection semantics |
| Filter deletion | WAL-backed DeleteByFilter with no-match success, current-version selection, cancellation, and reopen recovery |
| Index DDL | Atomic CreateIndex/DropIndex for unquantized Flat and supported scalar INVERT definitions, including full-snapshot validation |
| Column DDL | Atomic AddColumn arithmetic/NULL backfill, AlterColumn numeric rename/conversion, and physical DropColumn for six basic numeric types |
| Optimize | Atomic live-snapshot compaction, contiguous-ID run segmentation, deletion/superseded-version reclamation, and safe obsolete-artifact pruning |
| Recovery | One CURRENT commit point for every DDL/Optimize operation; subprocess kill tests cover both sides and cleanup retry |

INVERT postings are exact in-memory structures rebuilt from the consistent live
snapshot. The durable schema records their parameters, but v0.2 introduces no
separate posting file. This keeps Flush, DDL, Optimize, and reopen behavior
deterministic without stale auxiliary state.

## Explicitly unavailable

The following capabilities remain unavailable. Requested later index
algorithms return `ErrNotSupported`; v0.2 never silently substitutes Flat or a
forward scan. Unsupported column-type migrations are rejected during DDL
validation:

- FP16, INT8, INT4, rotation, RaBitQ, and PQ quantized execution;
- IVF and dense or sparse HNSW;
- HNSW-RaBitQ, Vamana, and DiskANN;
- FTS tokenization, parsing, postings, and BM25;
- the MultiQuery, RRF, weighted fusion, and callback-reranking execution surface;
- nonnumeric AddColumn/AlterColumn/DropColumn payload migration;
- reading or importing the C++ collection format.

Schemas may validate parameters for later indexes so applications can inspect
and round-trip baseline-compatible configuration. Query, build, Optimize, or
other operations that would have to execute an unavailable algorithm reject it
explicitly.

## Compatibility and verification

v0.2 preserves the public enum assignments pinned to C++ commit `58375ff`, the
v0.1 public Go method signatures, and native format version 1. Manifests written
by newer v0.2 operations include an optional writing-segment start ID; the v0.2
reader derives it for older v0.1 manifests, so deleted high document IDs are
never reused after a rewrite.

The release gate runs all package and example tests, `go vet`, the race
detector, active codec/expression/SQL fuzz targets, repeated subprocess crash
matrices, and no-CGO Darwin/Windows compilation. Deterministic regressions
compare forward and indexed filter results, validate CRUD and Flat results
through DDL/Optimize/reopen, inject publication failure, corrupt referenced
storage, and verify incomplete WAL recovery.
