# Stemmer token filter

The v0.5 stemmer token filter is a pure-Go implementation of the filter in
zvec commit `58375ff`. It vendors the official Go runtime and the 36 algorithms
generated by Snowball 3.1.1 at commit
`cd195b51e948a902a4312f023f4a14392516a543`. It does not use CGO, a native
libstemmer library, runtime dictionaries, or locale state.

`NewStemmerTokenFilter` validates the requested case-sensitive libstemmer name
or alias. An empty language selects `english`, matching the baseline's default.
Invalid names return an error matching `ErrInvalidStemmerOptions` rather than
silently disabling stemming.

```go
filter, err := core.NewStemmerTokenFilter(core.StemmerTokenFilterOptions{
    Language: "english",
})
if err != nil {
    return err
}
tokens, err := filter.Filter(ctx, []core.Token{
    {Text: "running", Offset: 0, Position: 0},
    {Text: "connections", Offset: 8, Position: 1},
})
```

`Filter` returns a new owned token slice and changes only `Token.Text`. It
preserves order, offsets, positions, and empty tokens. A filter is immutable
and safe for concurrent use; each call owns its Snowball environment.
Cancellation is checked before processing, while scanning large terms, and
between terms, and an interrupted call returns no partial result.

Snowball algorithms normally expect composed, lowercase UTF-8 text. Compose
token filters explicitly when needed: lowercase must run before the stemmer.
The stemmer does not itself normalize or lowercase terms. Valid UTF-8 has the
pinned libstemmer results. Malformed byte strings are accepted without a panic,
but Snowball defines linguistic stemming only for valid text.

The 36 canonical algorithms are Arabic, Armenian, Basque, Catalan, Czech,
Danish, Dutch, Dutch Porter, English, Esperanto, Estonian, Finnish, French,
German, Greek, Hindi, Hungarian, Indonesian, Irish, Italian, Lithuanian,
Nepali, Norwegian, Persian, Polish, Porter, Portuguese, Romanian, Russian,
Serbian, Sesotho, Spanish, Swedish, Tamil, Turkish, and Yiddish.
`SupportedStemmerLanguages` returns the complete sorted set of 115 canonical
names and ISO aliases accepted by the pinned baseline. Names are deliberately
case-sensitive. `porter` and `dutch_porter` remain separate compatibility
algorithms; `kraaij_pohlmann` is an alias for the current `dutch` algorithm.

The compatibility fixture records the zvec source, Snowball module table, all
algorithm-source identities, and a C-libstemmer result for every canonical
algorithm. Tests also exercise all aliases, the baseline English and German
examples, lowercase composition, malformed bytes, metadata and ownership,
cancellation, concurrent use, fuzzing, an example, and a throughput benchmark.
The vendored runtime and generated algorithms are covered by the Snowball
BSD-3-Clause text in `NOTICE`.

This unit provides the stemming primitive. Tokenizer-pipeline configuration,
posting lists, FTS parsing, BM25, and Collection FTS execution remain separate
v0.5 units.

```sh
go test ./internal/core -run '^TestStemmerTokenFilter|^TestSupportedStemmer'
go test ./internal/core -run '^$' -fuzz '^FuzzStemmerTokenFilter$'
go test ./internal/core -run '^$' -bench '^BenchmarkStemmerTokenFilter$' -benchmem
```
